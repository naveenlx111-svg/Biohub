# E0022: oracle fork-repair ceiling

E0022 freezes E0020 and uses ground-truth matching only as a diagnostic instrument. For each missed division, it searches the already detected parent/daughter lineage nodes for a consecutive local fork, removes conflicting incoming/outgoing edges, inserts the oracle fork, and evaluates the resulting graph with the patched official scorer.

This experiment cannot produce a submission. Its purpose is to measure how much division score is recoverable from existing detections, the exact adjusted-edge cost of correct rewiring, and how many false negatives have no usable consecutive fork geometry. A large oracle gain justifies building a learned candidate ranker; a small gain would redirect effort toward division-specific detection/localization.

## Result

The baseline scored `0.930240` locally: adjusted edge Jaccard `0.914855`, division Jaccard `0.153846`, and division counts `4 TP / 8 FP / 14 FN`.

Oracle rewiring scored `0.978697`: adjusted edge Jaccard `0.917158`, division Jaccard `0.615385`, and division counts `16 TP / 8 FP / 2 FN`. It repaired 12 missed divisions, while four were already true positives. One remaining event had no consecutive fork geometry and one lacked the required detection evidence.

This is decisive evidence that the current detector already contains enough lineage evidence to exceed the `0.95` target. The bottleneck is selecting and rewiring the correct division fork, not broad cell detection recall. The next production experiments should learn or strongly constrain fork selection; this oracle itself must never be submitted because it uses ground truth.
